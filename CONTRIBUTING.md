# Contributing to PySlate

Thanks for your interest in PySlate. Contributions, bug reports, documentation fixes, and reproducible test cases are welcome.

## Before opening an issue

- Check whether the issue already exists.
- Include your OS/device, app version, Python runtime version where relevant, and clear reproduction steps.
- Do not attach private projects, passwords, API keys, personal files, or other sensitive data.
- For a suspected security vulnerability, follow `SECURITY.md` instead of posting exploit details publicly.

## Development basics

- Keep changes focused and preserve the offline-first design.
- Do not add runtime accounts, telemetry, ads, paid APIs, or cloud dependencies without explicit project-owner approval.
- Keep Windows and Android behavior aligned where the shared interface is involved.
- Update third-party notices when adding or changing dependencies.
- Add or update tests for behavior changes; do not claim a test passed unless it was actually run.
- Avoid committing build outputs, local SDK configuration, generated test reports, or signing keys.

## Pull requests

Describe the user-visible change, implementation approach, tests run, and any platform limitations. If a test could not be run, state why. Screenshots or short recordings are useful for UI changes.
